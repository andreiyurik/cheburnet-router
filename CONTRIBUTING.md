# Как поучаствовать

Спасибо, что смотрите в эту сторону. Проект ведёт один человек в свободное время, поэтому здесь
коротко: что нужнее всего, как прогнать проверки и чего ожидать от ревью.

## Чем помочь, если вы не пишете код

- **Расскажите, где застряли при установке.** Это самая ценная обратная связь: цель проекта —
  чтобы роутер настраивал обычный человек, а не только программист. Пишите в
  [Telegram @industrialprofi](https://t.me/industrialprofi) или заводите
  [issue](https://github.com/andreiyurik/cheburnet-router/issues).
- **Сообщите о баге** — приложите диагностику из панели (кнопка «Собрать диагностику»; пароли и
  ключи из неё вырезаются автоматически, см. [Troubleshooting](docs/kb/reference/troubleshooting.md)).
- **Проверьте на своей модели роутера** и напишите, что получилось: модель, архитектура, версия
  OpenWrt, объём RAM/flash.
- **Поправьте документацию.** Непонятная глава — это баг; PR с правкой формулировки приветствуется.

## Если пишете код

Перед первым PR прочитайте [CLAUDE.md](CLAUDE.md) — там принципы, по которым принимаются решения,
и правила про язык, комментарии и совместимость с busybox. Кратко:

- **На роутер, логика** — ucode. **Bootstrap/glue** — POSIX sh + busybox-ash, shellcheck-clean.
  **Веб-мастер** — Svelte. **Python/Node на роутере нет** — их использовать нельзя.
- **Никаких GNU-only утилит** (`install -m`, `seq`, GNU-флаги `find`/`sed`) — busybox их не знает.
- **Идемпотентность:** повторный запуск любого шага чинит, а не плодит дубликаты.
- **Нейтральные формулировки** в коде, документации и UI — проект позиционируется как
  образовательный, про сетевые технологии. Подробно — раздел «Нейтральные формулировки» в CLAUDE.md.

### Проверки перед PR

```sh
make lint          # shellcheck + ucode -c
make test-engine   # юнит-тесты движка (секунды, роутер не нужен)
make test-shell    # тесты bootstrap-слоя
```

Меняли data-plane или `engine/steps/` — прогоните живой тест в QEMU:

```sh
make qemu-smoke    # движок через rpcd на реальном OpenWrt
make qemu-install  # полная установка + split реально работает
```

CI гоняет то же самое на push и PR.

### Коммиты и PR

- Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `test:` — как в `git log`.
- Один PR — одна тема. Большой рефакторинг лучше обсудить в issue заранее: у мейнтейнера
  ограниченное время на ревью, и отклонить готовый большой PR обиднее, чем обсудить идею.
- В описании PR: что ломалось, как проверяли, на каком железе/в QEMU.

## Чего ожидать

больше недели, пните в Telegram, это не игнор.
