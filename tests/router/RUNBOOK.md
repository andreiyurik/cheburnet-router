# RUNBOOK — проверка на физическом роутере через арендованный VPS

Это **исполняемый** сценарий, а не описание: каждый шаг — команда. Он существует, чтобы прогон
занимал вечер, а не выходные, и чтобы результат оставался в файле, а не в памяти.

Для AI-ассистента: выполняй шаги **по порядку**, не пропускай шаг 1 и шаг 2. Если шаг упал —
останавливайся и разбирайся, а не переходи к следующему: дальше пойдёт наслоение причин.

---

## Что проверяем и чего этим добиваемся

| Что | Почему только здесь |
|---|---|
| **PMTU на реальном канале** | у провайдера PPPoE/оверхед; симптом — «мелкие сайты открываются, крупные висят» |
| **AmneziaWG насквозь** | единственный протокол; стенд даёт свой сервер и ключи |
| **Смена сервера из панели** с автооткатом | на живом железе, а не в QEMU |
| **Сутки + перезагрузка** | ближе всего к обещанию «годы без обслуживания» |
| **Поведение на реальной arch** | QEMU — только x86_64; MIPS/ARM отличаются busybox и памятью |

---

## Предусловия

1. **VPS поднят** (сервер AmneziaWG):
   ```sh
   scp tests/vps/provision-lab.sh root@<vps>:/root/
   ssh root@<vps> 'bash /root/provision-lab.sh'
   bash tests/vps/fetch-links.sh root@<vps> [ssh-key]
   ```
   На выходе: `tests/vps/awg-client.conf` — credentials, в `.gitignore`, в репозиторий не попадает.

2. **Роутер доступен по SSH** с машины, где лежит репозиторий. Дальше во всех шагах:
   ```sh
   export R_HOST=192.168.1.1          # адрес роутера
   export R_KEY=~/.ssh/id_ed25519     # ssh-ключ (или добавьте свой ключ на роутер заранее)
   ```
   Пароль в переменной не поддерживается намеренно: он утёк бы в историю оболочки и в `ps`.

3. **Роутер не единственный источник интернета в доме на время прогона.** Kill-switch намеренно
   режет трафик при упавшем туннеле — это защита, а не сбой. Пока идут шаги 4–6, интернет может
   пропадать.

## Шаг 1. Инвентаризация (только чтение, ничего не меняет)

```sh
bash tests/router/inventory.sh
```

Что даёт: модель, arch, версия, свободные RAM/флеш, что уже установлено, и **вердикт preflight**.

**Решение по результату:** preflight не прошёл — сначала разобраться с причиной (флеш, RAM,
архитектура); soft-провалы можно пропустить осознанно, как в мастере.

## Шаг 2. Путь назад

```sh
bash tests/router/backup.sh
```

Снимает `sysupgrade -b` в `tests/router/results/` и печатает команду восстановления. **Не
пропускать:** дальше меняются `network`, `dhcp`, `firewall`, и путь назад не должен зависеть от
нашего же кода откатa.

## Шаг 3. Установка и проверка первого протокола

Сначала пакет — тем же путём, которым пойдут люди:

```sh
scp -O bootstrap/bootstrap.sh root@<роутер>:/tmp/
ssh root@<роутер> 'sh /tmp/bootstrap.sh'
```

Затем установка. Два равноценных пути — выбирайте по цели прогона:

- **как пользователь**, через веб-мастер `http://<роутер>/cheburnet/` (проверяет и веб-слой);
- **скриптом**, если прогон повторяется:

```sh
bash tests/router/install.sh
```

Скрипт зовёт тот же метод ubus, что мастер, и берёт `.conf` со стенда. Пароль root он генерирует и печатает (или задайте
`R_ROOT_PASS`); ключ SSH при этом не отзывается — вход по ранее положенному ключу продолжает
работать. **Положите свой ключ в `/etc/dropbear/authorized_keys` ДО установки:** она задаёт пароль
root, и беспарольный вход после неё закроется.

После успеха:

```sh
bash tests/router/verify.sh
```

Скрипт смотрит, какой туннель активен **сейчас**, и проверяет его насквозь: панель не врёт про
здоровье, трафик выходит **с адреса VPS**, крупная загрузка проходит целиком (PMTU), direct-домен
попадает в nftset (то есть split реально работает).


## Шаг 4. Смена сервера (и уход с legacy-протокола)

```sh
bash tests/router/switch.sh
bash tests/router/verify.sh
```

На AWG скрипт делает **замену сервера** (`replace_awg_conf`) тем же конфигом со стенда. Если роутер
ещё на замороженном Reality/Hysteria2 ([ADR 0010](../../docs/kb/decisions/0010-freeze-full-tier.md)),
это уход на AmneziaWG (`switch_to_awg`) — тот же путь, что у кнопки панели, с автооткатом.

## Шаг 5. Автооткат (проверка обещания панели)

Вставьте в панели **заведомо битую** ссылку (испортите один символ в `pbk` или пароле) и
переключитесь на неё. Ожидаемое поведение: туннель не поднялся → **прежний вернулся сам**, и
панель об этом сказала. Здоровье прежнего туннеля может секунд двадцать показывать `down` — это
окно до следующего handshake, а не отказ. Затем:

```sh
bash tests/router/verify.sh     # прежний протокол снова работает
```

## Шаг 6. Сутки и перезагрузка

Оставьте роутер работать. Через сутки — и **обязательно после физической перезагрузки**
(выдернуть питание честнее, чем `reboot`):

```sh
bash tests/router/verify.sh
```

Смотрите не только на «зелено», а на строку про помеченный трафик: именно здесь ловился дефект,
при котором split-tunnel выключался после каждой перезагрузки при полностью зелёной панели
(панель не врала — просто правила направления живут в ядре и исчезали). Если проверка ругается,
разбор — в [troubleshooting](../../docs/kb/reference/troubleshooting.md), раздел про direct-домены.

Прошло — закрыт самый дорогой пункт: «настроил один раз, работает без обслуживания».

## Шаг 7. Свернуть стенд

```sh
ssh root@<vps> 'bash /root/provision-lab.sh --teardown'
```

Пока сервис жив, **VPS работает открытым прокси для любого, у кого есть ссылка.** Закончили —
снимайте, а лучше удаляйте VPS целиком.

---

## Куда попадают результаты

Каждый шаг дописывает `tests/router/results/<дата>-<шаг>.md`: время, факт, цифры. Отчёты
**не коммитятся** (в них адреса и параметры сети) — из них руками переносятся ЦИФРЫ в ADR 0004,
раздел «Замеры». Долговечен вывод, а не лог.

## Если что-то упало

1. Соберите диагностику из панели (кнопка «Собрать диагностику») — секреты она вырезает сама.
2. Приложите отчёт прогона из `results/`.
3. Дальше — [troubleshooting](../../docs/kb/reference/troubleshooting.md).

## Что этот прогон НЕ проверяет

Устойчивость к фильтрации у **другого** провайдера. Результат «AWG поднялся» верен для вашей
сети и не переносится на чужую — это свойство сети, а не нашего кода.
