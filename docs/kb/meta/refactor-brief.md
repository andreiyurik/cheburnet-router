# 🧹 Брифинг рефакторинга (промпт для сессии с Claude)

Этот файл — **готовое задание**. Открой новую сессию в корне репозитория и дай ссылку на него:
«Выполни `docs/kb/meta/refactor-brief.md`». Всё, что нужно знать, — ниже; догадываться не надо.

## Цель

Сделать репозиторий **компактнее и удобнее для разработки с ИИ**, не меняя поведения продукта.
Три оси, в порядке приоритета:

1. **Комментарии — под ИИ, а не под человека-читателя.** Сейчас 20 % строк движка — комментарии,
   в отдельных файлах до 41 %. Много длинных повествовательных блоков.
2. **Дедупликация** там, где она реально есть (замеры ниже: движок чист, тесты — нет).
3. **Компактность и структура** — вкус «канонического Rails по DHH», адаптированный под
   ucode + Svelte на OpenWrt: мало файлов, очевидные имена, соглашение вместо конфигурации,
   никаких слоёв ради слоёв.

## Не-цели (не делай)

- Не меняй поведение data-plane. Ни одной правки семантики маршрутизации, kill-switch, DNS.
- Не выдумывай абстракции ради красоты. Порог — **3 повторения блока 5+ строк** или бизнес-инвариант.
- Не переформатируй файлы целиком: дифф должен читаться. Ширина 100 колонок, табы — как сейчас.
- Не трогай нейтральность формулировок (см. CLAUDE.md) и русский язык комментариев/документации.
- Не удаляй тесты, чтобы «стало компактнее». Тестов должно стать не меньше, а покрытие — не ниже.

## Ось 1. Комментарии под ИИ — доктрина

Доктрина (4 вида комментариев, что выкидываем, численные ориентиры) уже описана в CLAUDE.md,
раздел «💬 Комментарии» — используй её как есть, не изобретай заново. Ниже — то, что специфично
для этого рефакторинга: пример преобразования и список фактов, которые нельзя потерять.

**Пример нужного преобразования** (из `steps/singbox/singbox.uc`, было 16 строк — стало 3):

```
// БЫЛО: 16 строк про stack=gvisor — механика fw4, история поимки, цена, альтернативы.
// СТАЛО:
// ИНВАРИАНТ: stack="gvisor", не "system" — при auto_route=false пакет из TUN должен пройти
// input, а у fw4 там policy drop и TUN вне зон: TCP молча не идёт (UDP идёт → картина обманчива).
// подробно: [[0004-multi-protocol-tiers]]
```

**Что НЕЛЬЗЯ потерять** (перед сокращением найди и сохрани смысл; каждый пункт оплачен инцидентом):

- `steps/firewall/firewall.uc` — правила живут в `/etc/nftables.d/`, иначе умирают на `fw4 reload`;
  kill-switch ключуется по `oifname WAN`, не по LAN-CIDR.
- `steps/firewall/firewall.uc` + `install/reapply.uc` — ip-часть не переживает ребут, её
  возвращает hotplug-хук; гейт хука ждёт **оба** артефакта (правило и маршрут).
- `steps/singbox/*` — `auto_route=false`, `stack=gvisor`, предусловие WAN-дефолта.
- `steps/vpn/apply.uc` — teardown обязан вернуть WAN-маршрут и дождаться его.
- `lib/proc.uc` — `uci batch` возвращает 1 на любом выводе; толерантные чистки идут своим батчем.
- `steps/doh/doh.uc` — https-dns-proxy восстанавливает dnsmasq из своих backup-ключей на stop.
- `lib/route.uc`, `install/install.uc` — почему туннельные интерфейсы исключаются из детекта WAN.

3. **Чтение WAN из netifd** в `run.uc` и `reapply.uc` — один хелпер (место: `lib/route.uc`,
   там уже живёт чистый разбор `ip route`).
4. Пройди `web/src/` тем же скриптом (он ниже) — там замер не делался.

Скрипт замера дублирования (используй его же для отчёта «до/после»):

```bash
python3 - <<'PY'
import subprocess, re, collections
files=[f for f in subprocess.run(['git','ls-files'],capture_output=True,text=True).stdout.split()
       if f.endswith(('.uc','.sh','.js','.svelte')) and 'node_modules' not in f]
def norm(l): return re.sub(r'\s+',' ',re.sub(r'//.*|#.*','',l).strip())
b=collections.defaultdict(list); N=5
for f in files:
    ls=[norm(l) for l in open(f,encoding='utf-8')]; keep=[(i,l) for i,l in enumerate(ls) if l]
    for j in range(len(keep)-N+1):
        c=tuple(l for _,l in keep[j:j+N])
        if sum(map(len,c))>=110: b[c].append((f,keep[j][0]+1))
for cnt,c,loc in sorted(((len(v),k,v) for k,v in b.items() if len(v)>1), reverse=True)[:15]:
    print(f"×{cnt} {c[0][:80]}  →  {', '.join(f'{f}:{n}' for f,n in loc[:3])}")
PY
```

## Версия и релиз

По решению мейнтейнера этот рефакторинг выходит как **3.0** — в одном роутере сошлись три
протокола под разные сценарии (AmneziaWG, VLESS+Reality, Hysteria2), и это оправдывает мажор.

- `PKG_VERSION:=3.0.0` в `package/cheburnet/Makefile` (`PKG_RELEASE:=1`).
- Тег **`v3.0.0`**. Внимание на историю нумерации, чтобы не повторить чужую ошибку: теги линии
  `v2.x` (`v2.0.0`…`v2.4.0`) — это релизы **нынешней** архитектуры, а версия пакета шла отдельной
  дорожкой (0.2.0 → 0.6.0). С 3.0.0 две дорожки **сходятся**: тег = версия пакета. Зафиксируй это
  одной строкой в `docs/kb/meta/release-checklist.md`, иначе следующий читатель решит, что
  «3.0.0 < v2.4.0».
- Чек-лист релиза — `docs/kb/meta/release-checklist.md`, выполнять целиком, включая проверку, что
  `releases/latest/download/cheburnet.apk` отдаёт именно новый пакет.

## Порядок работы

Слоями, каждый слой — **отдельный коммит с зелёными гейтами**. Не сваливай всё в один дифф.

1. `refactor(engine): комментарии — только инварианты, квирки и шрамы` (по 2–3 файла за проход).
2. `refactor(tests): общая обвязка QEMU вместо копий` .
3. `refactor(engine): один вход для планов шагов` (если оказалось проще).
4. `docs`: перенос длинных объяснений в `docs/kb/` (правка CLAUDE.md под доктрину уже сделана —
   коммит `4971841`).
5. `chore(release): версия 3.0.0` + тег.

**Гейты после каждого слоя** (все обязательны, коды возврата смотреть напрямую — не через `| tail`):

```bash
make lint && make test-engine && (cd web && npm run test)
SSH_PORT=18022 make qemu-smoke      # живой OpenWrt, ~2 мин
SSH_PORT=18022 make qemu-reboot     # data-plane после ребута, ~7 мин
```

Перед 5-м слоем — прогон на физическом роутере по `tests/router/RUNBOOK.md` (стенд с тремя
протоколами поднимается сам: `tests/vps/provision-lab.sh`).

## Чего от тебя ждут в отчёте

Коротко и по делу: что сократилось (цифры), что дедуплицировано (адреса), что **решено не менять**
и почему (это тоже результат — например, если общий вход для планов оказался хуже шести врапперов).

рефакторинга.
