# ADR 0006 — Дизайн-система UI: shadcn-svelte в lite-варианте

> [!info] Статус: принято · Tailwind v4 + исходники компонентов shadcn-svelte, но без
> `tailwind-variants`, `tailwind-merge` и `bits-ui`. Уточняет [[0003-svelte-for-ui]]
> (Svelte остаётся), не отменяя его.

## Контекст

Интерфейс был собран на семи самописных компонентах (`web/src/lib/ui/`) и одном файле CSS на
400 строк. Он работал, но каждая новая форма требовала нового куска CSS, а состояния (загрузка,
пусто, ошибка) появлялись там, где про них вспомнили. Нужна была **система**, а не набор стилей:
одинаковые отступы, одинаковые состояния, одинаковые кнопки на всех шести экранах.

[shadcn-svelte](https://www.shadcn-svelte.com/) подходит по главному признаку — это **не
зависимость, а копия кода** в репозиторий. Для проекта с одним мейнтейнером это важнее удобства
обновления: библиотека может заглохнуть, свой код — нет.

Проблема в том, что апстрим-компоненты тянут за собой обвязку. Замер (gzip, один и тот же
проект, Vite 6 + Svelte 5):

| Что в бандле | gzip | прирост |
|---|---|---|
| Пустой Svelte-компонент (рантайм) | 11.5 КБ | — |
| + `cn()` = clsx + `tailwind-merge` | 20.3 КБ | +8.8 |
| + `tailwind-variants` | 33.0 КБ | +12.7 |
| Кнопка shadcn как есть | 32.5 КБ | +21 к рантайму |
| Та же кнопка на clsx + объекте вариантов | 12.0 КБ | +0.4 |
| Checkbox + RadioGroup на `bits-ui` | +5 КБ | |
| Dialog + AlertDialog на `bits-ui` | +20 КБ | |

То есть главный расход — **не компоненты, а машинерия стилей**: `tailwind-merge` разрешает
конфликты классов в рантайме, `tailwind-variants` строит варианты через DSL. На шести экранах,
где все классы пишем мы сами, разрешать в рантайме нечего.

## Решение

Берём у shadcn-svelte **разметку, рецепты классов и структуру API**, а обвязку заменяем:

1. `cn()` — это `clsx`, без `tailwind-merge`.
2. Варианты — обычный объект (`BUTTON_VARIANTS`), без `tailwind-variants`.
3. Интерактивные компоненты — на нативных элементах, без `bits-ui`:
   - модальное окно — `<dialog>` + `showModal()` (ловушка фокуса, Esc и затемнение — от браузера);
   - чекбокс и радио — настоящие `<input>` под прозрачным слоем, галочка нарисована CSS;
   - выпадающий список — `<select>` (на телефоне система показывает привычное колесо выбора);
   - сворачиваемые блоки — `<details>` (работают по якорю и без JS).
4. Иконки — инлайновые SVG, без иконочной библиотеки.

Цена редизайна: **JS 55.5 → 63.6 КБ gzip (+8.1), CSS 3.7 → 6.3 КБ gzip (+2.6)**. Прирост — это
код самих компонентов и строки классов; вся 21-килобайтная обвязка в бандл не попала.

## Последствия

- **Апстрим обновляется руками.** `shadcn-svelte add -o <имя>` вернёт версию с `tv()` — правки
  придётся перенести. Диффы читаемые: отличие — заголовок `<script module>` и вызов `cn`.
- **Конфликты классов не разрешаются.** `class="p-6"` поверх варианта с `p-4` выигрывает не
  всегда — побеждает порядок утилит в CSS. Поэтому отличия задаём **вариантом компонента**, а не
  перекрытием класса. Это записано и в комментарии к `cn` (`web/src/lib/utils.js`).
- **Доступность не пострадала, а выросла:** нативные контролы дают клавиатуру и скринридеры без
  единой строки ARIA, а `<dialog>` — ловушку фокуса, которой у прежней модалки не было.
- **Тема сохранена целиком.** Цвета [[web-theme|«плёнки-1969»]] переименованы в токены shadcn
  (`--background`, `--primary`, `--destructive`…); WCAG-тест `web/src/theme.test.js` переписан
  под новые имена и по-прежнему роняет сборку при падении контраста.

## Альтернативы

- **shadcn как есть** — ноль расхождений с апстримом, +25 КБ gzip. Отклонено: обвязка дороже
  того, что она даёт на шести экранах.
- **DaisyUI** (ноль JS, плагин Tailwind) — отклонено: приносит свой визуальный характер, а у
  проекта есть собственная палитра, снятая с кадров мультфильма.
- **Melt UI / headless** — это и была прежняя ситуация: стили пишем сами, системы не возникает.
- **Flowbite, Skeleton, Carbon, Material** — тяжелее и с чужим характером; поддержка соло.
